# Домашнее задание к занятию «Базы данных, их типы» - `Амосов И.А.`

---
Кейс:
Строительная компания организует архитектуру работы с данными. Нужно подобрать СУБД под каждую задачу.

1.1. Бюджетирование, финансовая аналитика и прогнозирование рисков

Для этой задачи оптимально использовать реляционную СУБД - Post greSQL.
Строгая схема данных, поддерживает транзакции с ACID-свойствами, подходит для построения отчётности, многопользовательских операций и аналитики

1.1.* Хеширование замедлилось. Как ускорить?

Для ускорения операций хеширования можно использовать Redis в качестве кэш-сервиса 

1.2. Лендинги и CRM-система

Mongo DB  как NoSQL


1.2.* Можно ли использовать одну СУБД?

Да, MongoDB можно использовать как для хранения данных лендингов, так и для CRM-системы

1.3. База нормативной документации и обучающих материалов

целесообразно использовать реляционную СУБД, PostgreSQL
Позволяет структурировать данные 

1.3.* Можно ли использовать существующую СУБД?

Да, можно задействовать ту же PostgreSQL-базу, создав отдельную схему или новую таблицу для корпоративных материалов, без необходимости развёртывания отдельного сервиса

1.4. Логистика: маршруты и доставка

Лучше всего использовать графовую базу данных или реляционную СУБД с поддержкой графовых расширений -  PostgreSQL с дополнением Apache AGE


1.4.* Можно ли подключить отдел закупок к этой же СУБД?

Да, закупки можно интегрировать в общую графовую модель

1.5.* Можно ли решить все задачи одной СУБД?

Полностью закрыть все задачи одной системой затруднительно. На практике стоит использовать гибридный подход:

PostgreSQL для строгих структурированных данных (финансы, логистика, нормативка),

MongoDB для гибких данных лендингов и CRM.



Задание 2. Транзакции
2.1. Процесс пополнения баланса телефона:

Пользователь вводит номер телефона и сумму пополнения

Система проверяет корректность номера и его наличие в базе

Банк или платёжная система блокирует указанную сумму на счёте пользователя

Оператор связи принимает запрос и предварительно зачисляет средства

После подтверждения оператором банк окончательно списывает средства

Пользователь получает уведомление об успешном пополнении

2.1.* Процесс автоплатежа:

Пользователь настраивает автоплатёж заранее, выбрав дату и сумму

В установленный день система автоматически инициирует процесс списания

При недостатке средств отправляется уведомление пользователю

При успешном списании средства зачисляются оператором автоматически

Пользователь получает уведомление о пополнении баланса

Задание 3. SQL vs NoSQL
3.1. Пять преимуществ SQL-систем по сравнению с NoSQL:

Строгое определение структуры данных через схемы таблиц

Поддержка транзакций с гарантиями целостности (ACID)

Возможность строить сложные запросы и отчёты с использованием вложенных запросов и объединений

Чёткая типизация данных снижает вероятность ошибок

SQL запросы в конце концов

3.1.* Преимущества NewSQL-систем:

оризонтальное масштабирование NoSQL с надёжностью транзакций SQL

Поддержка полноценной совместимости с SQL-языком запросов

Повышенная производительность за счёт распределённых вычислений

Автоматическое шардирование и балансировка нагрузки 

Эффективная работа в условиях высоких нагрузок и большого объёма данных

Задание 4. Кластеры
Работа с большим объёмом данных на 1000 машин:

Основным критерием выбора СУБД будет линейная масштабируемость и отказоустойчивость. Для хранения данных оптимальны NoSQL-системы вроде Cassandra или ScyllaDB, которые обеспечивают равномерное распределение нагрузки между узлами

Для вычислений подойдёт Apache Spark благодаря поддержке параллельной обработки данных в памяти
